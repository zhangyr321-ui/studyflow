# StudyFlow 作品集仍需补充的材料

当前文档已经根据真实项目代码、版本历史和需求讨论完成初稿。为了制作正式投递版，还需要以下材料。

## 1. 必须补充

### 个人信息

- 姓名或作品集署名
- 目标岗位名称
- 工作年限或应届/转行背景
- 联系方式是否需要出现在作品集

### 项目信息

- 正式在线体验网址
- 你希望展示的项目起止时间
- 是否允许公开 GitHub 仓库
- 是否已有真实试用者；如果有，只写可验证的数量和反馈

### 截图

请使用演示数据准备以下手机截图：

1. 主页完整页面
2. 今日任务和小型计时器
3. 进度页的任务、项目和科目
4. 计时结束保存记录表单
5. 日统计连续时间轴
6. 周统计或月统计
7. 复盘记录和错误标签
8. 学习笔记图文页面
9. 模考趋势页面
10. 异常计时警告页面

截图前请隐藏真实日记、个人备注、考试信息和其他隐私内容。

## 2. 建议补充

- 一张手绘草图、早期页面或需求讨论截图，用来展示迭代过程。
- 一张修改前后的对比图，例如固定纵轴与动态纵轴。
- 1～2 条真实试用反馈，必须获得对方同意并匿名处理。
- 你申请岗位的招聘描述，便于调整作品集重点和关键词。
- 个人简历，用于统一项目描述、语气和视觉风格。

## 3. 不应虚构

- 用户数量
- 日活、月活或留存率
- 收入和商业转化
- 团队成员和岗位分工
- 未执行过的用户访谈或可用性测试
- 没有实际接入的 AI、数据库和登录功能

## 4. 推荐目标岗位版本

### 产品经理

强化需求取舍、业务规则、核心流程、验收标准和迭代案例。

### AI 产品经理

增加 AI 协作开发方法、提示约束、结果验收和未来 AI 功能边界。

### 产品运营

增加用户使用路径、激活漏斗、内容运营设想和数据指标体系。

### 产品设计 / UX

增加低保真原型、信息架构、状态设计、移动端交互和视觉前后对比。

## 5. 下一步制作顺序

1. 收集并脱敏截图。
2. 根据目标岗位调整主案例叙事。
3. 将 `00_CASE_STUDY.md` 制作成手机友好的作品集网页。
4. 同步生成 PDF 版本。
5. 准备3分钟讲解稿和针对岗位的面试问答。
