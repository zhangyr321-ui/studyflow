# StudyFlow 账号与云端同步改造计划

## 当前基线

- 前端：原生 HTML、CSS、JavaScript。
- 当前数据：`localStorage` 中的 `studyflow-mobile-v1` 完整状态对象。
- 现有备份：JSON 导出与导入。
- 本次开发分支：`feature/auth-cloud-sync`。
- 目标：邮箱账号登录 + 云端保存 + 跨设备恢复，保留现有页面和学习功能。

## MVP 技术方案

使用 Supabase Auth 负责账号与会话，使用 PostgreSQL 保存数据。首版将现有完整状态对象作为一份 JSON 文档存入 `public.studyflow_user_data`，每个用户对应一行。这样可以先保留当前业务数据结构，避免为科目、任务、日记等内容立即进行大规模拆表。

数据库表的 RLS（行级安全）策略只允许已登录用户访问 `user_id = auth.uid()` 的记录。浏览器端只能使用 Supabase 项目 URL 和 publishable/anon key；绝不能把 `service_role` key 放进前端代码或公开仓库。

## 数据安全规则

1. 每次保存先写入本地，避免网络短暂中断时丢失正在编辑的内容。
2. 未登录时继续使用现有本地模式，不删除已有数据。
3. 首次登录时，分别检查本地和云端是否已有数据；不得静默覆盖任意一方。
4. 若需要用云端数据替换本地数据，先导出本地 JSON 备份并取得用户明确确认。
5. 登录后只同步当前账号自己的数据；退出登录不删除本地数据。
6. 网络失败时保留本地数据，并清楚显示同步失败状态。
7. 在启用自动同步前，处理多设备同时编辑的冲突，避免简单的无条件覆盖。

## 实施顺序

1. 创建 Supabase 项目，并在 SQL Editor 执行 `supabase/schema.sql`。
2. 添加浏览器端 Supabase 配置与账号界面。
3. 接入注册、登录、退出、会话恢复和错误提示。
4. 接入首次数据迁移、云端读取、保存与同步状态。
5. 验证两台设备同步、断网恢复、退出登录、本地备份和不同用户的数据隔离。
6. 配置正式部署域名和 Supabase Auth 的允许重定向地址。
